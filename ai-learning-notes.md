# AI + Learning Notes

## Example 1: Choosing the asset
- **I asked:** "I have 48 hours and ₹2,000 to get 500 final-year students to register. What should I build besides a landing page?"
- **AI suggested:** A tracker dashboard, referral links, and a WhatsApp flow.
- **I changed:** I picked the tracker so I could show which channel is working. I labeled the 12 starting records as sample data and added a note that entries save only in the browser, so demo numbers aren't mistaken for real results.

## Example 2: Rejecting an AI suggestion
- **I asked:** "How should I generate campaign suggestions in the dashboard?"
- **AI suggested:** Connect an AI API to generate them.
- **I changed:** I used rule-based logic instead. It costs nothing, needs no API key, and doesn't imply intelligence the prototype doesn't have.

## Example 3: Fixing a misleading metric
- **I asked:** "What should the referral table show?"
- **AI suggested:** A conversion rate per referral code.
- **I changed:** I show registrations and each code's share only. I don't track visits or clicks, so a conversion rate would be a made-up number.

## Example 4: Improving the message
- **I asked:** "Write a WhatsApp message to get final-year students to register."
- **AI suggested:** A long, salesy message with many emojis.
- **I changed:** I cut it to 4 lines, led with the "live link for your resume" hook, and added a referral code so each ambassador's sign-ups can be tracked.

The dashboard's campaign suggestions are rule-based, not generated by an AI API.

## What I learned
- Before accepting an AI suggestion, I check whether it fits the budget, timeline, and what I can actually measure.
- Metrics need accurate labels: without click data, registration counts can't show a conversion rate.
- Prototype data and campaign targets are assumptions, not results.
